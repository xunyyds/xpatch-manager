# 备份与导出

## 备份

入口：设置 → 备份与恢复 → 备份数据。点击后先弹「备份范围」，勾选要写入备份的内容并显示各项体积，确认后由系统「另存为」创建 ZIP。

### 范围

| 范围 | 内容 |
|---|---|
| 设置 | 外观、打包、作用域与历史偏好，`SettingsStore` 的全部键 |
| 作用域与模块 | 模块开关、模块→应用作用域、应用→模块 API 级别、模块保护记录 |
| 签名 | 默认签名档，自定义签名档的名称、密码、算法与证书文件 |
| 打包历史与导出记录 | `patch-history.json` 全量，含每次打包参数与导出位置 |
| 打包产物 | 历史记录仍在磁盘上的 APK 文件，勾选时自动带上打包历史 |
| 操作日志与崩溃记录 | `events/operations.log` 与 `crash/` 下的堆栈 |
| 运行日志 | 目标应用 `Android/data/<包名>/.logs/<模块>/*.log`，需「所有文件访问」权限，只备份不还原 |
| 仓库缓存 | 模块仓库索引与模块说明文本 |

默认勾选除「打包产物」「运行日志」外的全部范围；这两项体积不可控，由用户在弹窗中自行决定。

### 包内布局

```
manifest.json                 格式标识、创建时间、版本、范围与条数
settings.json                 设置
scope.json                    作用域、模块 API、模块保护记录
signatures.json               默认签名与自定义签名元数据
signatures/<id>.bin           自定义证书文件
history/patch-history.json    打包历史
artifacts/<记录 id>/<文件名>   打包产物
logs/operations.log           操作日志
logs/crash/<文件名>            崩溃记录
logs/runtime/<应用>/<模块>/<文件>  运行日志
cache/repo-cache.json         仓库索引
cache/readmes/<包名>.txt       模块说明
```

`manifest.json` 写在包首，恢复前的预览只读取这一个条目。

### 恢复

入口：设置 → 备份与恢复 → 从备份恢复。选中文件后先解析 `manifest.json`（旧版配置文件则按 JSON 解析），弹窗列出范围与条数并提示「恢复会覆盖当前对应数据」，确认后才执行。

- 设置逐键覆盖，缺失的键保持当前值；
- 作用域与模块 API 恢复前先清空，避免旧数据残留；
- 自定义签名按记录重建证书文件，并清理不再被引用的旧证书；
- 打包历史整体替换，包内带产物时在解包阶段就直接落回输出目录并改写路径、大小与修改时间，大小与记录不符的产物会丢弃并告警；
- 操作日志、崩溃记录整体替换；
- 仓库索引与说明整体替换；
- 运行日志只备份不还原；
- 恢复后重新同步目标应用的作用域文件（含被移出作用域的应用），并让历史、仓库索引的内存缓存失效；
- 导出目录的 SAF 授权不随备份迁移，恢复不会改动当前导出目录；
- 解包上限 4096 个条目（运行日志不计）、3 GB，超出即中止，避免异常压缩包撑满存储；运行日志条目只识别不落盘。

旧版 `xpatch-backup.json` 仍可通过同一入口恢复，按覆盖语义还原作用域、模块 API、默认签名与部分设置。

## 导出目录

设置 → 备份与恢复 → 导出目录，通过系统目录选择器指定，保存的是 SAF 持久授权。

- 打包完成后产物在写入应用私有输出目录的同时，复制一份到所选目录，并计入该记录的第一条导出记录；
- 打包历史与打包完成弹窗里的「导出」直接写入所选目录，不再落到私有目录；
- 未设置或授权失效时回退到私有输出目录；
- 换目录时释放旧目录的持久授权；长按条目清除所选目录并释放授权；
- 授权失效（例如重装应用）时条目显示「权限已失效，请重新选择」。
