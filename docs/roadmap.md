# 产品路线图

本项目的目标是在保留完整模块能力的基础上持续做加法。下面把「基础能力」与「差异化能力」分开列出，作为验收清单。

## 一、基础能力

| 能力 | 说明 | 状态 |
| --- | --- | --- |
| 应用注入 | 选择已安装应用或外部 APK，注入内核并重新签名 | 已完成 |
| 补丁配置 | Hook 核心（LSPlant / LSPlant NoInline / Pine）、过签方案（seccomp / hook / none） | 已完成 |
| 作用域管理 | 模块 × 应用的作用域开关，按应用持久化 | 已完成 |
| 模块 API 适配 | 按应用选择 API 89 / 100 / 101 / 102 适配层 | 已完成 |
| 签名配置 | 内置兼容密钥库，支持自定义密钥库的增删改与默认切换 | 已完成 |
| 安装流程 | 打包后由用户选择直接安装 / 打开方式 / 导出，安装前做签名比对提示 | 已完成 |
| Shizuku 支持 | 检测与授权，作为免 Root 的提权通道 | 已完成 |
| 日志 | 打包与作用域操作日志 | 已完成 |
| 仓库管理 | 模块仓库浏览 | 待接入 |
| 用户体系 | 多用户 / 工作资料（分身）场景 | 待接入 |

## 二、差异化能力

| 能力 | 价值 | 状态 |
| --- | --- | --- |
| Android 17 支持 | 内核在 Android 17 完成适配并通过真机验证 | 已完成 |
| 全源码开源 | 内核、引导桩、管理器均为可读源码，无混淆 | 已完成 |
| 全新 Compose 界面 | Material3 动态取色、LSPosed 风格信息结构 | 已完成 |
| 打包前静态校验 | 注入后的 dex / 清单可在安装前离线校验，避免装完才发现问题 | 已完成 |
| 多签名并行管理 | 任意数量自定义签名，随时切换默认项 | 已完成 |
| 逐应用模块 API 覆盖 | 同一模块可在不同应用中用不同 API 适配层 | 已完成 |
| 安装前签名预判 | 提前告知签名冲突，允许用户自行决定 | 已完成 |
| 失败可诊断 | 打包/安装失败给出明确阶段与原因 | 已完成 |

## 三、尚未开始但已规划

1. **模块仓库**：在线模块索引、版本更新、一键安装；
2. **批量操作**：多应用批量注入、批量更新、批量卸载；
3. **命令行接口**：本机 CLI，便于自动化；
4. **崩溃归因**：注入后应用异常时自动定位是否为内核导致。

## 四、工程原则

- 新增能力优先做「可验证」：每一处改动都要能用日志或离线校验证明；
- 第三方代码与资产一律显式署名：登记到 `ACKNOWLEDGEMENTS.md`，源文件保留 SPDX 头；
  不以改名、去标识的方式处理来源问题。
